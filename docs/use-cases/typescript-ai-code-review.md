# TypeScript AI Code Review: Type Safety, Suppression, and Structural Integrity

Engineering Intelligence provides deterministic TypeScript code review for AI-generated codebases. It detects `as any` casts that hide type mismatches, `@ts-ignore` suppressions that mask real errors, unawaited async calls, and structural anti-patterns that degrade long-term TypeScript codebase health.

TypeScript's type system is a fundamental engineering control. AI agents systematically undermine it when generating code that "just needs to work" — suppressing type errors to make the compiler pass without addressing the underlying incompatibility.

---

## TypeScript-Specific Failures Engineering Intelligence Catches

### 1. `as any` Type Casts (`CODE-006`)
The most common TypeScript anti-pattern in AI-generated code. Agents cast to `any` when they cannot correctly infer the type, bypassing the entire type system at that point:

```typescript
// What the agent writes:
const userId = (session as any).user.id;
const result = JSON.parse(rawData) as any;
const handler = (req as any).context.tenant;
```

**Real-world impact**: The mistyped property causes a `TypeError: Cannot read properties of undefined` at runtime in a production environment.

### 2. `@ts-ignore` and `@ts-expect-error` (`CODE-006`)
Agents use compiler directives to suppress type errors it cannot resolve:

```typescript
// @ts-ignore - agent couldn't figure out the union type
const response = processEvent(payload);
```

**Detection**: Scans for suppression directives and flags them for human review. Distinguishes between blanket `@ts-ignore` (always flagged) and contextual `@ts-expect-error` (flagged unless justified).

### 3. Unawaited Async Function Calls (`CODE-007`)
In TypeScript codebases, agents call `async` functions without `await` inside synchronous event handlers, discarding both the return value and potential rejections:

```typescript
// Event handler — sync context
export function onUserCreated(user: User) {
  sendWelcomeEmail(user);   // Promise<void>, not awaited
  updateAnalytics(user.id); // Promise<void>, not awaited — errors vanish
}
```

### 4. Single-Implementation Generic Interfaces (`ARCH-001`)
Agents produce TypeScript interfaces that add indirection without polymorphism:

```typescript
// Generated by agent:
interface IEmailService {
  send(to: string, subject: string, body: string): Promise<void>;
}

class EmailService implements IEmailService { ... }
// Only one implementation exists, no mocks, no alternates
```

### 5. Circular Type Imports (`ARCH-003`)
TypeScript modules that mutually import each other's types cause initialization order issues in module bundlers and Next.js/Vite edge runtimes.

## Why This Matters for TypeScript Codebases

TypeScript's value proposition is catching type mismatches at compile time. Every `as any` cast is an agreement to trade that safety guarantee away. In large AI-generated codebases, `as any` accumulates — initially in "just one place," then propagates as other agents reuse the pattern.

Engineering Intelligence enforces the **zero-suppression** baseline by default and tracks suppression density as a codebase health metric.
