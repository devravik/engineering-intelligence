# Cursor Code Quality & AI Composer Review

Engineering Intelligence is a deterministic quality control and review tool built for developers using Cursor, Cursor Composer, and Cursor Agent. It catches architectural over-engineering, security vulnerabilities, database performance traps, and UI slop before changes are accepted.

Cursor's multi-file edits and Composer capabilities allow rapid feature development, but frequently introduce architectural sprawl: redundant single-use abstractions, unbounded external API calls, missing permission checks, and generic purple AI UI aesthetics.

---

## Quick Installation for Cursor

Install the skill for Cursor:

```bash
npx skills add devravik/engineering-intelligence
```

Or run the installer to generate native Cursor rules:

```bash
npx @devravik/engineering-intelligence install
```
This automatically configures `.cursorrules` / `.cursor/rules/engineering-intelligence.mdc` in your workspace.

## What Cursor Developers Catch with Engineering Intelligence

When Cursor Composer generates code across multiple files, Engineering Intelligence evaluates the cross-file impact:

* **Single-Implementation Interfaces (`ARCH-001`)**: Composer frequently creates speculative interfaces for simple services when no polymorphism or alternative implementation exists.
* **Missing Authorization on Endpoints (`API-001`)**: When scaffolding new Next.js route handlers or Express routers, Cursor often omits role-based access control or session verification.
* **N+1 Database Queries (`DB-002`)**: In ORM query builders (Prisma, Drizzle, TypeORM), loops containing `.findUnique()` queries inside mapping routines.
* **Unbounded HTTP Calls (`API-005`)**: Using `fetch` without `AbortSignal.timeout(5000)` or timeout handlers, causing hung connections during upstream latency.
* **AI UI Slop (`UI-COLOR-001`, `UI-SLOP-003`, `UI-SPATIAL-001`)**: Formulaic purple-to-indigo gradients, excessive card wrapping, and rigid centered layouts.

## Using Engineering Intelligence in Cursor

### In Cursor Terminal
Run against unstaged or staged changes generated by Composer:

```bash
$ ei detect --changed

Engineering Intelligence

NEW  DB-002    N+1 query
     src/api/users.ts:84

NEW  API-001   Missing authorization check
     src/routes/projects.ts:42

2 findings detected.
```

### In Cursor Composer Prompt
Reference your `.cursorrules` to instruct Cursor:
```text
Run `ei detect --changed` on the files you just edited and fix any detected architecture or security issues before stopping.
```

### Enforcing the Ship Decision
```bash
$ ei ship
BLOCK: UNKNOWN != PASS (Resolve 2 findings before shipping)
```
